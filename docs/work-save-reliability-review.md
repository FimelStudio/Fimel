# 作品草稿保存可靠性修复

2026-11-19 至 20 日。基线 `f501a00`；分支 `fix/work-save-reliability-20261119`，回滚标签 `baseline/work-save-reliability-20261119`。

## 已确认的问题与证据边界

用户编辑「Fimel 桌游馆」正文后，第一次保存出现 Failed to fetch，第二次长时间停在处理中。对用户已登录的普通 Edge 进行只读检查，控制台中对应 `/api/works/…` 保存请求出现 `net::ERR_TIMED_OUT` 和 `net::ERR_CONNECTION_RESET`；后续只读作品库查询也未在时限内完成。检查时按钮已经恢复，页面仍显示未保存的更改和本机恢复记录。没有刷新页面、读取或导出 Cookie，也没有代用户保存或发布正式内容。

匿名连接测量中，后台域名 DNS 解析用了约 0.14 秒，但 12 秒内未建立 TCP 连接；官网首页同次返回 HTTP 200，整体耗时约 11.6 秒。此测量反映当时本机到站点的链路不稳定，不能据此认定唯一故障位于本机、Cloudflare 边缘或源站，也不能证明保存请求一定未在服务端提交。

代码确认此前修复覆盖作品发布的等待上限与结果核对，作品草稿保存仍直接等待无时限的公共 `api()`。网络错误没有统一友好提示，也没有在保存响应丢失后核对实际持久化结果。仅添加登录提示、重试或延长等待不能解决这些缺口。

## 本轮修改

- 公共 API 为响应头和响应正文设置同一截止时间，兼容调用者取消；即使底层传输不响应 abort，也会结束前端等待。网络中断转换为中文提示，保留明确的身份、HTTP 错误及冲突信息。普通请求默认上限 60 秒。
- 作品保存最多等待 30 秒；断线、超时或不确定服务端错误后，用一个最多 15 秒的只读请求核对服务器作品。明确的 4xx 不当作成功。不会自动重复提交保存请求。
- 核对比较全部实际内容，忽略服务器保存时间戳；允许其他管理员已合并的不重叠修改，拒绝把旧正文、缺失作品或同字段冲突误判为本次保存成功。核对不成时保持本页编辑和原始保存基线，后续保存继续使用三方冲突检查。
- 保存期间展示正在保存／正在核对两个阶段，并允许导出当前修改。成功和失败都会退出忙碌状态；单篇作品保存和核对的网络等待上限合计 45 秒，浏览器暂停或系统休眠时间不包含在此保证中。
- 相同内容的手动重试由服务器直接返回现有草稿，不生成重复备份或更新时间；包括首次创建已成功但返回丢失、第二次仍携带空基线的情况。不同内容仍执行原有冲突保护。
- 首次保存尝试复用审计已读取的库快照，减少一次完整 R2 读取；条件写入冲突后仍重新读取并合并。
- 服务端增加写入开始／结束的请求编号、状态与耗时日志，并通过响应头返回编号。日志不记录正文、身份断言、Cookie、密钥或文件内容。
- 作品发布沿用 90 秒提交＋20 秒核对时限，并共用有截止时间的 API；大文件完整校验单独保留 10 分钟上限，避免误用普通请求上限。

原有备份、条件写入和审计顺序保留。全库仍使用一个私有 JSON 对象存储，保存需要全库验证、备份和条件写入；本轮没有迁移数据库。随着作品数量和正文增大，按作品拆分持久化可以另作性能改进，不能把这种结构直接认定为此次连接重置的原因。

## 存储语义

核对通过后台直连 R2 绑定读取，不经公开 CDN。参照 [R2 一致性文档](https://developers.cloudflare.com/r2/reference/consistency/)与 [Workers R2 API](https://developers.cloudflare.com/r2/api/workers/workers-api-reference/)：成功提交后可读取最新值；一次未读到预期内容不能证明先前仍在途的写入永远不会提交。因此核对失败使用「结果未确认」，并继续保留条件写入与三方合并保护。
