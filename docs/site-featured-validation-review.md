# 网站精选分组校验修复

2026-10-27。开发基线 `913ad41`，分支 `fix/site-featured-validation`，回滚标签 `baseline/site-featured-validation-20261027`。两份用户交接文件保持未跟踪且未修改。

## 实际问题

只读核对正式公开 manifest：`fimel-card` 已公开，类型为 `datapacks`、状态为 `released`，当前版本 `26.3-v1.0`，有 4 条公开发行记录；它不是尚未发布。截图把它放在“精选地图”，而该组既有规则限定已发行的基岩版地图。服务端把类型错误和发行状态错误统称“精选分组与作品发行状态不符”，客户端又允许任何分类加入任何组，造成误解。

公开网站内容还保留 `fimel-card` 的原“制作中的作品”推荐引用，作品发行后该项也需要移组。网站内容和作品各自独立发布；仅发布作品不会自动改动首页人工推荐。

## 修复范围

1. 官网展示与 Admin 共用原有精选分组规则，保持筛选行为和页面布局。`maps` 为已发行基岩版地图，`released` 为已发行作品，`development` 为制作中／企划中作品；不新增作品分类，不修改现有内容。
2. 网站内容接口返回当前公开作品快照。编辑器优先以官网实际分类和发行状态显示状态与筛选候选，避免把私有草稿中的改动当作已经公开的状态；尚未公开作品仍可保存为网站推荐草稿。
3. 已保存的不匹配选择保留原值并明确显示“已公开，但分类不适合”或“已公开，但发行状态不适合”；真正缺少公开记录时才提示尚未公开。保留未知／不匹配项供修改，不静默删除。
4. 提供显式“移至已发行作品”等操作：从其他组移除同一 slug，在目标组保留已有位置或追加一次，保留其他推荐顺序。目标组满 12 项时禁用操作；仅修改本机网站编辑区，不自动保存或发布。
5. 添加“刷新作品公开状态”，保留正在编辑的网站文案、推荐和原私有保存基线；如果其他管理员修改了网站草稿，仍返回冲突并阻止覆盖。预览与确认发布前重新读取公开快照并校验，服务端保留同样的最终检查。
6. 将后台“已发行软件与模组”改名为覆盖数据包的“已发行作品”，各组说明明确范围。移除误用的通用版本冲突提示；操作开始或编辑后清除旧网站成功提示，进入网站编辑时清除其他作品发布留下的全局消息，避免旧的“发布成功”与新错误混在一起。

## 立即可用的操作

现有线上后台不必重新发布 Fimel Card。将 `fimel-card` 从“精选地图”和“制作中的作品”移除，加入现有“已发行软件与模组”，再按“保存网站草稿 → 预览网站发布 → 确认发布网站内容”操作即可。作品正文、版本和发行文件保持原样。
