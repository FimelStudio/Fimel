## 范围与操作

### 官网下载区

已发行版本有文件时，可以选择最新可下载版本或历史版本，查看游戏版本、加载器、运行平台、发布日期、文件大小及 SHA-256，并下载每个文件。字段来自后台保存的真实版本数据，不推测兼容性；没有文件的版本不会遮挡已有下载入口。

没有结构化版本记录的作品保留原主下载方式及已有元数据，三个原发行文件地址不变。只读检查当前公开目录：28 个作品、没有结构化发行版本、没有网站内容设置；新解析器兼容。要展示历史版本，需要管理员正常添加版本、关联文件并确认发布，不会自动改写现有作品。

### 后台六项

1. 发布状态：区别未保存、已公开且已同步、有修改待发布及历史版本待核对；显示编辑、保存和发布时间。新发布使用内容指纹建立对照，旧作品不会自动重发。
2. 发布预览：对照当前官网与已保存草稿，支持三语、桌面／手机宽度、正文差异、图片轮播和多文件版本信息；Markdown、轮播、下载组件和版本正文生成复用官网／发布代码。预览禁止实际下载。原始 JSON 作为折叠的辅助检查。
3. 编辑恢复：未保存作品与网站内容按已验证身份、标签页分别保存在当前浏览器 IndexedDB，保留 7 天；新标签页不会清掉其他窗口的编辑，重新打开可选择恢复。恢复后保存仍核对远端基线。存储失败明确提示。后台每分钟及重新聚焦时检查版本，仅提示更新，上传或未保存网站内容时不会强制刷新。
4. 多人编辑：前端改为按作品提交，服务端保留 R2 条件写保护；不同作品的并发修改保留，同作品非重叠字段合并，同字段冲突显示基线、服务器和本机内容。选择后回到编辑区核对，再保存；不做盲目覆盖。原全库 API 保留供兼容和既有迁移使用。
5. 网站内容：新增独立编辑页，管理三组首页精选及顺序、工作室／联系三语文案、公开联系方式、近期更新。保存只写私有草稿；预览确认后独立更新公开目录中的网站内容，不重发作品正文和文件。近期更新是用户明确追加允许的官网展示区，没有条目时不显示。网站草稿有备份与恢复，发布有日志。
6. 图片与统计：图片标明封面、正文所在语言／页签、未使用候选，支持定位引用；正文仍使用时先删除引用再移除关联，历史文件保留。按作品分别汇总详情浏览、下载点击、Cloudflare 文件请求及流量，支持筛选和 CSV 导出。详情／点击不回填历史，不解释为独立访客或完整下载人数。

- 官网 Worker 增加 `POST /api/work-events` 和 OPTIONS，限定官网、www 与现有 GitHub Pages Origin，只接受已公开作品，下载点击还要求有公开下载。
- 已获确认并启用公开桶绑定 `PUBLIC → fimel-downloads`；限流绑定 `METRICS_LIMITER` 使用已核实未占用的 `11002`、每边缘位置同来源 IP 每 60 秒 45 次。
- 计数以 R2 条件写入 `metrics/works/YYYY-MM-DD.json`，仅保存按日、按作品聚合的浏览／点击数字；不保存 IP、邮箱、Cookie、用户标识、访客明细或下载文件内容。该桶本来公开，因此聚合计数也视为公开数据。
- GitHub Pages 上报到官网同一采集接口；本地开发和 localhost 构建预览默认不上报生产。短时间 React 重挂载去重；采集失败不影响详情和下载。
- 此计数是尽力采集的事件数，可能受限流、网络、拦截器或并发失败影响，不能当作审计级账本。文件请求仍来自已有 Cloudflare 只读分析，分片和续传分别计入请求；原下载累计展示来源保持兼容。
- 不创建 D1、不迁移 Supabase、不引入长期凭据、不启用付费订阅、不扩大 Access 白名单或修改登录有效期。

## 更新后的操作路径

- 修改作品 → 保存草稿 → 查看“有修改待发布” → 发布预览，对照当前官网 → 确认发布。保存草稿始终只更新后台。
- 发行版本 → 添加版本，填写版本号、游戏版本、加载器和平台（多项用逗号分隔）→ 保存草稿 → 上传该版本文件 → 保存 → 设置为已发行 → 保存并预览发布。未发行版本及其文件保留私有；空文件版本不会顶替实际下载。
- 网站内容 → 调整精选顺序、三语工作室／联系文案或近期更新 → 保存网站草稿 → 预览网站发布 → 确认发布网站内容。精选与近期更新引用的作品须先公开。
- 图片用途标签可跳到正文引用。删除正文图片只修改 Markdown；移除未使用候选只解除草稿关联，不删除历史对象。
- 遇到同字段冲突，查看三方内容并选择使用服务器版本或保留本机冲突字段，检查后再保存。意外关闭后，在同一浏览器登录同一管理员可恢复本机编辑；不能代替服务器草稿或跨设备备份。
