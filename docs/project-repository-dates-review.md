# 项目仓库与首次发布日期交付审阅

2026-10-27。开发基线 `690245f`，分支 `feat/project-repository-and-dates`，回滚标签 `baseline/project-repository-dates-20261027`。本轮不修改两份未跟踪的用户交接文件。

## 实际问题

现有 `Project` 已支持 `repository`，官网也已有仓库按钮，但 Admin 只能通过完整 JSON 维护。此次将仓库地址放入“基本信息”，新增作品与已有作品均可填写；按钮沿用原官网位置与样式，名称改为三语通用“项目仓库”，支持其他 HTTPS 代码托管网站。

只读核对公开 manifest：`fimel-card` 和 `simple-replay-datapack` 均为已发行且有公开版本，但缺少 `published` 字段。它们的更新时间均为 `2026-10-27`；Fimel Card 的公开版本日期最早为 `2026-10-26`，Simple Replay Datapack 为 `2026-10-27`。原右栏只读取缺失的字段，因而显示“尚未公布”。最近一次发布时间不能代表首次发布，不能用于填充。

## 修改行为

- Admin 新增可选的“项目仓库地址”和“首次发布日期”，复用原字段，没有新增 Schema 或迁移正式数据。仓库地址有 HTTPS／无用户名密码校验和打开核对入口；清空后保存会移除字段。
- 保存草稿仍只进入私有库；确认发布后，仓库按钮才更新到官网。发布预览复用官网仓库组件，禁用跳转，支持三语与当前官网对照；清空字段也计入变化摘要。
- 官网、Admin 发布预览与服务端发布共用日期逻辑：显式 `published` 优先；已发行作品缺失时，取公开、已发行且有文件的版本中最早的有效日历日期。版本顺序不影响首发日。新代码上线后，两篇作品无需重发正文即可分别显示 `2026-10-26`／`2026-10-27`。
- 重发时优先保留原公开作品的已知日期（包括从旧公开版本推得的日期），移除最早版本也不会将首发日推迟。手工填写的纠正日期优先。读取不改写私有草稿；`updated` 仍按原规则随正式发布更新。
- 制作中、计划中或无可靠发行记录的作品不使用今天、创建日、更新时间或最近发布时间猜测首发日期。若先下架移除公开记录、又删掉全部历史版本，且私有记录未填写首发日，则需要手动补充真实日期。
