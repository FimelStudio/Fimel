## 使用方式

已保存、已公开且未归档的非网易基岩版作品，在“基本信息”中查看当前官网下载数，输入希望显示的当前值，经明确确认后单独应用。校正不随保存草稿触发，也不发布正文、版本或网站文案。支持设为 0，官网仍沿用零值隐藏；网易基岩版地图保留原有商店下载量编辑方式。

校正成功后，后续真实下载继续累加；管理员日志记录操作者、作品、校正基数、日期和结果。原日统计及 Admin 所选日期区间里的真实浏览／点击记录保持原样。

## 存储与并发

复用现有 PUBLIC／PRIVATE R2 绑定，不新增数据库、资源、密钥或权限。PUBLIC 的 `metrics/download-corrections.json` 单独保存版本化校正记录，只含创建校正时已公开的作品 slug、目标基数、UTC 锚定日、该日已采集点击数、时间和随机操作 ID。作品日后下架不删除历史记录，公开统计接口只返回当前公开作品。原因与操作者仅记入现有私有管理员日志，不放入公开文件。

官网计算方式为“校正基数＋锚定日后续新增点击＋之后日期的点击”，不改写或删除 `metrics/works/` 的真实日记录。例如锚定当日已有 10 次点击，校正为 100，后来当日新增 3 次、次日新增 2 次，官网显示 105。再次校正以新的时间锚点生效。

校正记录用 R2 条件写防止多人覆盖，依赖 [R2 的强一致性及原子条件写](https://developers.cloudflare.com/r2/reference/consistency/)；同一操作 ID 重试保持幂等，冲突后保留输入并要求重新核对。校正先经过现有 Access、管理员白名单和 CSRF 检查，并写入准备审计记录；校正数据的 ETag 参与公开接口 revision 与内部缓存键，避免继续命中校正前的缓存。分段历史读取只加一次基数，目录变化或校正变化时不混合不同版本。响应丢失后可重试同一操作或重新读取核对，已成功的校正不会因重读而重新锚定。
