# 作品页返回首页后的导航稳定性

日期：2026-10-11。本轮只调整路由转场，不更改作品内容、字体、品牌视觉、Supabase 或部署逻辑。

## 观察与边界

反馈场景：作品页停留较久，再进入首页加载缓慢；加载期间重新进入作品页，顶部导航仍在，但正文持续空白。

线上入口仍使用等待式页面转场。检查发现 `PageTransition` 把实时读取路由上下文的 `Outlet` 放在 `AnimatePresence mode="wait"` 的退出树中：新路由挂载与旧动画完成绑定，且装饰幕布没有独立的超时清理。普通慢加载及快速切换测试在旧实现下也能通过，因此不能把这一代码风险当作已完全复现的线上唯一原因。

故障注入另模拟幕布动画冻结：旧实现始终保留覆盖层，测试失败；修改后的实现会移除覆盖层，测试通过。这验证了清理机制的有效性，不代表已经测得用户设备长期停留时的真实浏览器内部状态。

## 本轮调整

- 最新路由立即挂载，旧页面及 Canvas 立即卸载，不排队等待其他页面的退出动画。
- 保留原主题幕布、350ms 缓动揭幕和 200ms 内容淡入；改成独立 CSS 转场，不依赖 Motion 的退出完成回调。
- 正文默认可见，幕布默认收起；动画不支持或关闭时不会留下不透明正文／遮挡层。
- 幕布另设 600ms 定时清理，切换路由时取消旧定时器；后台定时器受到浏览器节流时按实际调度恢复执行。
- `prefers-reduced-motion` 直接禁用上述转场。首页原有 Three.js 延后加载、错误降级和 TNT 交互未改动。

## 验证

- `npm run build`、`npm run lint` 通过；27 条作品及 226 条资源／正文路径检查通过。
- 新增 5 项导航测试：首页模块请求挂起时返回作品、连续多次导航、动画帧中断、冻结幕布清理、模拟 30 分钟后台停留后的往返。
- 新导航测试全部通过；原有 7 项 3D 加载／降级测试另行通过。
- 最终 `npm run test:e2e` 完整 53 项通过（2.2 分钟），包含原有 48 项及新增 5 项导航测试。
- 根目录生产构建中模拟首页模块下载挂起及多次往返，最终正常展示 27 条作品；浏览器异常为 0。
