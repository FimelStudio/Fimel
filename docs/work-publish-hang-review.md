## 只读诊断

按用户要求，直接使用已经登录的普通 Edge 窗口，通过该窗口的 DevTools 发出同源只读查询；没有重开登录窗口、使用无痕档案、读取或导出 Cookie、验证码或 Token，也没有保存或发布真实内容。

卡住的是 Fimel Card **作品发布**弹窗，不是文档中心。`GET /api/library` 返回 200，草稿已保存于 `2026-11-18T13:56:57.530Z`；当前记录有 32 张私有图片和 4 个已发行文件。公开记录仍为 11 月 15 日的版本。日志中多次 `publish` 只有 `prepared` 开始记录，没有结束记录；相邻保存操作均为成功。重新登录不能解决这类请求等待。

代码确认存在两个问题：仅改文字重新发布时，对每个私有资源先调用 R2 `get` 打开完整文件流，再检查是否已有公开副本；存在副本时直接返回，既不消费也不释放该流。前端发布请求没有超时，而且错误提示位于弹窗背后的页面，不能及时恢复操作。

未取得这些历史请求的平台终止错误码，不把 CPU 限制、连接限制或客户端中断认定为已经证实的唯一原因。[R2 API 说明](https://developers.cloudflare.com/r2/api/workers/workers-api-reference/)区分只读元数据的 `head` 与含正文的 `get`；当前[连接限制说明](https://developers.cloudflare.com/workers/platform/limits/#simultaneous-open-connections)不将已收到响应头的正文流继续计入待响应连接数，因此也不以“未读正文恰好占满六个连接”作为结论。

## 修改

- 先用私有 `head` 验证尺寸、类型、归属、版本与校验元数据，再检查公开副本。复用副本时不打开私有正文。公开副本同时核对 assetId、类型、尺寸及 SHA-256，继续禁止覆盖不可变对象。
- 只有确实缺少公开副本时才 `get` 并流式复制，复制前重新检查源 ETag 与元数据；源改变或条件写入拒绝时释放未消费的流。未改旧的纯公开资源兼容分支。
- 浏览器发布请求等待上限 90 秒；之后最多用 20 秒重新读取公开结果。以服务端持久化的作品发布指纹核对，而不是把断网或超时直接当作失败。不会自动重复提交发布。
- 明确的身份、验证和版本冲突错误保留原文。无法确认时说明草稿已保存，恢复按钮并提示核对后重试。服务器已经明确返回成功但刷新失败时，区分“操作已确认”和“状态未刷新”。
- 发布／核对提示与错误置于弹窗内的固定操作栏，等待期间 Esc 不关闭弹窗。完成时如果另一个管理员修改了草稿，保留本页及原始编辑基线，下一次保存继续触发三方冲突检查。
