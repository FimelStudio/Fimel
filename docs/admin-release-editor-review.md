# Admin 发行版本编辑修复与优化

2026-10-26（Asia/Shanghai）。基线 `c3677b6`，分支 `fix/admin-release-workflow`，回滚标签 `baseline/admin-release-workflow-20261026`。两份用户交接／任务文件保持未跟踪且未修改。

## 问题核实与实施计划

截图中的错误由新增版本默认 `label: ''` 与原共享 Schema 的非空格式要求冲突导致。新版本尚未保存时，原上传 input 被 `savedVersionIds` 静默禁用；版本号为空又无法保存，形成操作死结。保存当前作品时原先会校验整个本机编辑库，另一个作品未完成的版本信息也会阻断当前作品。

1. 调整私有草稿校验，同时维持公开发行版本的安全路径约束。
2. 上传前复用单作品保存与冲突检测，保存成功才创建上传会话。
3. 抽出版本管理组件，使用版本列表与单版本表单，集中管理文件、兼容信息和日志。
4. 验证连续新版本、批量文件、草稿恢复、冲突与取消，复核原图片／发布流程及生产 CSP。

界面沿用既有 Geist、Lucide、语义颜色、4px 小圆角、深浅主题与响应式表单，不新增依赖。操作顺序参考 [GitHub 发行管理文档](https://docs.github.com/en/repositories/releasing-projects-on-github/managing-releases-in-a-repository)中的草稿、附件与确认发行；保留 Fimel 现有统一版本列表和发布预览流程。

## 最终行为

- 多个未命名的私有版本可保存、刷新恢复；空草稿不算重复版本号。非空版本号仍限安全字符，已发行版本必须填写版本号，同一作品的非空版本号仍不可重复。错误改为中文，并标明作品、版本与修正方法；输入旁提供提示和无障碍错误关联。
- 添加版本后立即选中，文件选择框可直接使用。选择或拖入文件后先检查类型／大小，再保存当前作品的私有草稿；成功后才校验并上传。冲突和保存失败不创建会话，保留本机编辑；保存有同步锁避免重复提交。
- 文件可批量选择／拖入，每版本最多 30 个。首文件默认主下载，移除主下载关联后选择剩余首文件。保留原分片、续传、校验与不可变资源协议。上传完成仍需要保存关联，再打开发布预览确认公开；不自动发行作品。
- 左侧版本列表显示版本号、日期、文件数和状态；右侧仅显示当前版本的基本信息、文件、兼容信息和三语日志。支持最新版本调整、下载验证、SHA-256 展开和关联移除。手机单列排列，保留键盘切换与焦点。上传期间禁用切换和移除；准备保存时沿用既有表单锁定。
- 旧作品实际下载／平台入口继续保留预览，新作品已有版本草稿时不再重复展示空下载区。官网展示组件、作品内容和发布规则沿用原实现。

## 发布与当前编辑保护

当前仅本地完成开发和验收，未合并 main、推送或部署。建议本次发布只更新现有 `fimel-admin` 的代码与静态资源；不批量保存、重发或覆盖任何作品，不修改官网功能、凭据、DNS、Access、R2 绑定与历史对象。部署前再次记录线上版本与绑定，沿用保留 Secret 的版本上传和流量切换流程。

用户当前旧后台页面可能仍有未保存编辑。部署不会主动刷新页面；应先用“导出当前修改”备份，再刷新新版。未命名私有版本的本机恢复记录在新版按新规则校验，可恢复后保存；导出文件保留完整内容，不要直接无确认覆盖服务器现有作品。上传已验证但尚未保存的关联也应一并保留在导出中。重新发布作品仍由管理员检查后自行确认。

代码回滚可使用基线标签。若使用新版保存了空版本号草稿，旧 Schema 无法继续保存这些草稿，因此回滚前应保留导出并先补齐版本号或另行制定兼容方案；代码回滚不会恢复或删除内容和文件，不自动清理未命名草稿。
