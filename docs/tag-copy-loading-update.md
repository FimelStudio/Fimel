## 3D 与前景加载分离

`src/components/DeferredScene.tsx` 是首页和关于我们装饰场景的共同边界：

1. 前景先绘制；两个动画帧之后等待 1.5 秒，受限设备等待 2.5 秒，再在浏览器空闲时请求 3D 模块。
2. 导航、主题切换和首屏内容不等待 Three.js 或纹理；离开页面会取消尚未启动的请求。
3. 场景仅在视区且标签页可见时启动。纹理尚未就绪不进行持续渲染，正常就绪后保留原场景与 TNT。
4. 模块失败、渲染异常、WebGL 不可用、上下文丢失或活动状态下加载超过八秒，均退回主题一致的静态背景。失败处理局限于装饰 Canvas。
5. `prefers-reduced-motion` 或浏览器省流量设置使用静态背景，不自动下载场景模块。
6. 首次进入的短遮罩不再拦截操作；它原有的固定退出时间不依赖场景就绪。

TNT 悬停光标仅作用于 Canvas，退出、点击和卸载会清理，不再在场景降级后影响全站鼠标。

延迟启动改善加载优先级，不会消除 Three.js 本身的解析和 GPU 开销；八秒定时器也不能阻止浏览器主线程或显卡驱动自身长时间阻塞。仍需真实手机与上线后用户数据进一步验证。

随机场景不保证恰好有 TNT 落在可点击视区。渲染测试先记录原场景，再在必要时仅在测试浏览器中定位一个现有 TNT；使用真实鼠标点击验证引信与爆炸，未直接调用事件处理函数，未改变生产方块分布。该测试不代表真实设备的 FPS、内存或 Core Web Vitals。

本轮本机验证产物位于已忽略的 `.artifacts/`；不会随网站公开部署。首轮结果保存在 [首轮验证记录](./frontend-verification.md)，不作为本轮性能数据。
