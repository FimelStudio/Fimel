## 性能改动

- 路由懒加载，Markdown 仅在详情页加载，Three.js 仅在有场景的页面加载。生产网络检查确认作品目录不提前加载 3D 或 Markdown 渲染器。
- 移除会把 React 公共依赖递归带入 Three.js 分块的旧手动分块规则，改用 Vite 自动分块与明确的懒加载边界。
- 首页先显示文案与入口，3D 使用独立异步边界；保留原有体素内容和 TNT 交互。
- 普通方块使用实例化绘制；离开视区或切到后台时暂停持续渲染。低性能手机减少背景方块并限制像素比。
- 合并鼠标更新、缓存交互边界、清理监听，减少悬停逐帧测量和布局属性动画。
- 手机与 reduced-motion 使用相应降级；缩短初始遮罩，避免等待大量图片后才开放内容。
- JSON、Markdown 和图片按需请求，正文会话缓存，列表不实例化逐卡片入场动画。

`node scripts/performance-smoke.mjs` 已针对根路径生产预览通过。桌面测试使用 Edge headless 软件 WebGL、1440×960、固定测试随机种子 42；该种子只在测试浏览器中设置，方便验证没有被首屏文字挡住的 TNT 表面。

| 一帧渲染采样 | 127 draw calls，4,584 triangles；并非全时段最大值 |
| 主题切换 | Canvas 正确切换 `#0d1117` / `#f4f4f5`，不重建 Canvas store |

这是单次本地实验，不是上线后的真实用户数据，不代表所有设备上的分数，也不是与原站的严格前后对照。TBT 不能当作真实 INP。评分 100 也不等于完整的 WCAG 或独立详情 SEO 已实现。

仍需处理的明确开销：

- 原始 Bingo PNG 约 984KB，作品列表另有约 442KB、439KB、394KB 的地图封面；本次保留原图，没有新增压缩派生尺寸。应优先准备不改变视觉内容的响应式图片，避免小缩略图下载高清原图。
- 首页按需 Three/Float 代码传输约 233KB；软件 WebGL 环境下主线程执行成本仍明显。后续应实测真机，再决定首屏场景的延后启动和进一步降级规则，保留可用交互。
- 公共入口压缩传输约 206KB，现有动画 UI 仍有执行开销；作品页虽不加载 Three.js，但还有进一步拆分公共动画逻辑的空间。
- 非计分检查仍提示生产 source map 缺失，以及语言按钮可见标签匹配警告（`ZH` 与 `切换语言 (ZH)`）；应作为后续人工无障碍复核项，不能仅依据总分忽略。

完整本机报告保存在 `.artifacts/lighthouse-home.json`、`lighthouse-works.json`、`lighthouse-summary.json` 和 `performance-smoke.json`；这些是已忽略的验证产物，不随站点公开部署。

## 部署与限制

Cloudflare 构建命令仍为 `npm run build`，部署命令仍为 `npx wrangler deploy`。默认根目录 base 为 `/`；GitHub Pages 工作流为其构建注入仓库子目录。Supabase 业务逻辑、Worker 定时任务、Wrangler 配置和 JAR 流式下载逻辑没有修改。

继续使用 HashRouter 保证两种静态部署下的深链接与刷新可用。详情会更新浏览器标题，但哈希详情地址还不是独立的服务端 HTML，因此不能宣称每个作品都拥有独立可抓取 SEO 和 Open Graph。需要此能力时，应单独规划预渲染及部署路径迁移。

真正的管理后台需要服务端身份验证和写入权限；GitHub 凭证不得进入网页、JSON 或 `VITE_` 变量。当前可以直接编辑仓库里的 JSON 和 Markdown，再由现有流水线部署。
